# Практическая работа 3

## Запуск локальной среды

Docker socket даёт Jupyter права управления Docker-хостом и по уровню риска близок к root-доступу.

Из корня репозитория задайте токен и подготовьте сеть и Linux volume моделей:

```sh
export JUPYTER_TOKEN="$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')"
export DOCKER_GID="$(getent group docker | cut -d: -f3)"
docker network create practice3-private 2>/dev/null || true
docker volume create practice3-ollama-models
docker compose -f practice_3/compose.yaml build
docker compose -f practice_3/compose.yaml up -d
```

Откройте `http://127.0.0.1:8890` и введите `JUPYTER_TOKEN`. 





В работе сравниваются две модели, которые по фотографии определяют,
является самолёт гражданским или военным:

- Qwen2.5-VL-3B-Instruct (`qwen2.5vl:3b`);
- Gemma 3 4B IT (`gemma3:4b`).

Цель — сравнить качество ответов, время обработки и поведение моделей
при ухудшении изображения. Обучение и дообучение моделей не выполняются.


## Данные и условия эксперимента

Используются 30 фотографий из тестовой части FGVC-Aircraft 2013b:
15 гражданских и 15 военных самолётов. Состав выборки и метки сохранены
в `data/manifest.csv`.

Среди гражданских самолётов есть пассажирские и региональные типы,
среди военных — Eurofighter Typhoon, F-16, F/A-18, Tornado, Spitfire
и Hawk T1. Бинарная метка назначена по типу самолёта и не описывает
фактическое использование конкретного борта.

Для проверки устойчивости подготовлены ещё 10 изображений:
по пять преобразованных снимков каждого класса. Используются:

- снижение яркости до 20% исходной;
- поворот на 35°;
- гауссово размытие с радиусом 5 пикселей;
- уменьшение длинной стороны до 96 пикселей с восстановлением размера;
- снижение яркости до 25% вместе с поворотом на −30°.

Каждое преобразование применяется к одному гражданскому и одному
военному самолёту. Полученные копии позволяют сравнить ответ до и после
изменения изображения, но не увеличивают число независимых исходных снимков.

Обе модели получают один и тот же запрос и должны вернуть метку
`civilian` или `military`. 

Перед отправкой изображения с длинной стороной более 896 пикселей
уменьшаются и сохраняются в памяти как JPEG с качеством 85.
Остальные передаются без изменения байтов. Исходные файлы сохраняются.


## Результаты сохранённого расширенного запуска

| Показатель | Qwen2.5-VL-3B | Gemma 3 4B |
|---|---:|---:|
| Правильные ответы на исходных снимках | 30/30 | 28/30 |
| Правильные ответы на преобразованных снимках | 9/10 | 9/10 |
| Правильные ответы на всех изображениях | 39/40 — 97,5% | 37/40 — 92,5% |
| Медиана времени последней попытки | 77,32 с | 47,13 с |
| Максимум времени последней попытки | 101,54 с | 94,47 с |

Qwen показала более высокую общую точность, а Gemma отвечала быстрее.
Обе модели ошиблись на A330-300 после снижения разрешения. Gemma также
ошиблась на исходных фотографиях Boeing 757-200 и ATR-72.
Во всех случаях гражданский самолёт был отнесён к военному классу.

На преобразованных изображениях модели получили одинаковые 90%.
При этом у Gemma одна новая ошибка компенсировалась исправлением другой:
после размытия ATR-72 был распознан правильно.

Результаты относятся к небольшой фиксированной выборке, поэтому нельзя
утверждать о превосходстве одной модели на любых изображениях
или устойчивости к каждому виду искажения.

## Файлы

- `practice3.ipynb` — подготовка данных, запросы к моделям,
  расчёт метрик, графики и выводы.
- `ollama_runtime.py` — создание или запуск контейнера Ollama
  и проверка среды.
- `compose.yaml` — конфигурация Jupyter.
- `Dockerfile.jupyter` — образ Jupyter с Docker CLI.
- `data/images/` — исходные фотографии; в эксперимент входят
  только снимки, перечисленные в манифесте.
- `data/transformed/` — преобразованные копии.
- `data/manifest.csv` — состав основной выборки, метки
  и контрольные суммы.
- `data/manifest-extended.csv` — состав расширенной выборки
  и параметры преобразований.
- `data/results.csv` — результаты отдельного раннего опыта
  на 30 исходных фотографиях.
- `data/results-extended.csv` — результаты расширенного опыта:
  40 изображений для каждой из двух моделей.

Два файла результатов относятся к разным запускам. Их не следует
объединять в одну оценку качества или использовать для прямого сравнения
времени между запусками.

## Подготовка среды

Текущая конфигурация рассчитана на Linux-окружение Docker
с доступом к NVIDIA GPU. Команды ниже выполняются в Bash;
для Windows потребуется соответствующая среда WSL2/Docker.

Для сборки должен быть доступен базовый образ
`practice2-nx-cugraph:25.4.0`, указанный в `Dockerfile.jupyter`.
Его подготовка осуществляется в `practice_2/Dockerfile.gpu`.

Jupyter получает доступ к `/var/run/docker.sock`, чтобы запускать
контейнер Ollama из блокнота. Это даёт коду в Jupyter широкие права
управления Docker-хостом, поэтому следует запускать только доверенные
блокноты.

Из корня репозитория выполните:

```bash
export JUPYTER_TOKEN="$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')"
export DOCKER_GID="$(getent group docker | cut -d: -f3)"

docker network inspect practice3-private >/dev/null 2>&1 \
  || docker network create practice3-private

docker volume create practice3-ollama-models
docker compose -f practice_3/compose.yaml build
docker compose -f practice_3/compose.yaml up -d
```

Откройте `http://127.0.0.1:8890` и введите значение `JUPYTER_TOKEN`.

## Запуск эксперимента

1. Откройте `practice3.ipynb`. Рабочим каталогом ядра должна быть
   папка `practice_3`.
2. Выполняйте ячейки последовательно. Сначала проверяются данные
   и создаются преобразованные изображения.
3. Ячейка подготовки среды запускает Ollama. Отсутствующие модели
   загружаются при последующей подготовке запросов.
4. После двух проверочных запросов запускается основной сбор:
   по 40 изображений на каждую модель.
5. Последние ячейки строят метрики, матрицы ошибок и сравнение
   исходных изображений с преобразованными.


Запросы выполняются последовательно, пакетами по два.
Между пакетами предусмотрена пауза 90 секунд. Только эти паузы
занимают 58 минут 30 секунд за полный сбор, поэтому запуск может
продолжаться несколько часов.

При некоторых временных ошибках допускается одна повторная попытка
после паузы 120 секунд. Промежуточные результаты сохраняются
в `data/results-extended-partial.csv`. Этот файл сохраняет уже собранные
ответы, но автоматического продолжения с места остановки код не выполняет.
Успешный полный сбор перезаписывает `data/results-extended.csv`.


## Остановка

Остановить Jupyter:

```bash
docker compose -f practice_3/compose.yaml down
```

Контейнер Ollama создаётся отдельно из блокнота и этой командой
не останавливается. Для его остановки выполните:

```bash
docker stop practice3-ollama
```

Модели сохраняются в томе `practice3-ollama-models` и могут использоваться
при следующем запуске.
